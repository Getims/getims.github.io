# DungeonJourney

Веб-игра для Poki.com (ПК + мобильный браузер), не плейбл: рекламных сетей нет, реклама только через Poki SDK. Unity-файлов здесь нет.

Клон Dungeon Descent (CrazyGames) → затем отличия DungeonJourney. Правила плейблов из `PLAYABLE_BASE.md` применять только там, где они не противоречат вебу/Poki.

## Перед работой прочитать

- `../../Docs/POKI_BASE.md` — правила веб-игр для Poki и какие модули `rules/` применять.
- `../../Docs/PLAYABLE_BASE.md` — индекс общих правил; из `../../Docs/rules/` читать только модули текущей задачи.
- `Docs/GAME_BRIEF.md` — ГДД этой игры (черновик, сверяется с медиа на этапе 2).
- `Docs/PLAN.md` — этапы, статусы, что заморожено (если работа поэтапная, см. `rules/stages.md`). Работать только в рамках текущего этапа.
- `../../Modules/README.md` — готовые модули: подключать их, а не писать заново.

## Правила

- Общие правила (`../../Docs/`, `../../Modules/`, `../../Template/`) не копировать в проект и не править попутно. Нужна особая версия модуля — копия внутри проекта. Находки по общим файлам — в «Находки по воркфлоу» в `Docs/PLAN.md`.
- Перед крупными системами — предложить варианты и дождаться выбора; неясное — спрашивать (см. «Работа с заказчиком» в `PLAYABLE_BASE.md`).
- Сборка: `npm run build` → `Build/index.html` (только сама игра); отчёт веса и скрины теста — в `BuildReport/`. Код игры — `Game/`, утилиты разработчика — `Tools/`, настройки сборки и теста — `Config/`.
- **Автотест — только текущий этап:** `npm test -- stageN`. Полный прогон (`npm test`) — на релизе или по явной просьбе. Сценарии этапа — отдельным блоком под фильтром `stageN` в `Config/test.config.mjs`. Тесты без просьбы не добавлять (см. `rules/acceptance.md`).
